# Changelog

Описание релиза на GitHub берётся из раздела этого файла для версии из `extension/manifest.chrome.json`. Релиз без записи здесь не публикуется.

## Не выпущено

Изменения сервера и шлюза. Расширение не меняется, его версия остаётся 2.0.9.

### Шифрование cookie

- Cookie Claude каждого пользователя теперь шифруются ключом, выведенным из его собственного пароля к шлюзу (scrypt и AES-256-GCM). Раньше общий ключ `COOKIES_KEY` лежал в `.env` рядом с файлами и попадал в каждый бэкап и снимок диска, поэтому копия диска давала доступ ко всем сессиям. Теперь без пароля пользователя файл не расшифровать. Ключ существует только в памяти шлюза, пока пользователь активен, и стирается через час без запросов. Имя пользователя и метаданные защищены от подмены.
- Файлы старого формата перешифровываются сами при первом запросе пользователя.
- `install.sh` больше не создаёт общий ключ `COOKIES_KEY` для новых установок. На старых установках он ставит ночную задачу `admin.sh retire-legacy-key`. Задача ждёт, пока ни одна сессия Claude больше не зависит от ключа, затем удаляет его из `.env` и из сохранённой конфигурации контейнера шлюза. После этого задача заменяет бэкапы, в которых был ключ, свежим бэкапом и удаляет себя. Файлы без сессии (пользователь не входил в Claude) при этом очищаются.
- Удаление пользователя стирает его файл cookie. Раньше файл переносился в `.removed/` и оставался действующей сессией.
- `caddy hash-password` получает пароль через stdin, а не в командной строке, которую видно в `ps`.

### Пользователи без перезапусков

- Добавление, смена пароля и удаление пользователя больше не перезапускают Caddy и шлюз. Caddy перечитывает настройки через свой сокет внутри контейнера (`admin unix//run/caddy/admin.sock`), а шлюз отзывает доступ только одного пользователя: его CONNECT-токены, туннели, WebSocket и WebSocket-cookie. Остальные пользователи соединений не теряют.
- При смене пароля сессия Claude сохраняется, если пользователь был активен в последний час.

### Панель управления

- Новая локальная панель `dashboard/dashboard.js` показывает пользователей и нагрузку: запросы, ошибки, ответы 429 от Claude, WebSocket, туннели, трафик, время ответа, соединения front door, CPU и память контейнеров и сервера. Из неё можно добавить или удалить пользователя, сменить пароль, снять бан IP. Панель работает на компьютере администратора и обращается к серверу только по SSH через `server/admin.sh`. На сервере не открывается новых портов. Описание: [docs/DASHBOARD.md](docs/DASHBOARD.md).
- В шлюзе появились счётчики нагрузки с историей за 24 часа и служебный API на `127.0.0.1:8089` внутри контейнера.

- Панель запоминает сервер. Для запуска двойным щелчком добавлены `dashboard/start.command` (macOS, Linux) и `dashboard/start.cmd` (Windows). При первом запуске панель спрашивает адрес сервера, а при ошибке входа по SSH подсказывает, что сделать. Пошаговая установка описана в README, раздел «Панель управления».

### Установщик

- Исправлено: при обновлении `install.sh` копировал новые `gateway.js` и `port443-mux.py`, но не перезапускал их, и до ручного перезапуска работал старый код. Теперь установщик перезапускает шлюз и front door и перечитывает Caddyfile. Порядок обновления описан в README, раздел «Обновление сервера».

### Обновление

- Нужны новые `gateway.js`, `admin.sh`, `add-user.sh`, `remove-user.sh`, `install-lib.sh`, `compose.yaml` (tmpfs `/run/caddy` для Caddy) и Caddyfile из нового шаблона. `install.sh` ставит всё это сам. Caddy после обновления нужно один раз пересоздать: `docker compose up -d`.

## 2.0.9 — 2026-10-16

Найдено полным аудитом: все хосты из фронтенда Claude сверены со списками расширения и шлюза, затем проведена сквозная проверка под входом в Chromium и Firefox (страницы, настройки, артефакты, загрузка файла, веб-поиск, WebSocket).

### Артефакты, голос, терминал

- Исправлено: в Chrome-сборке не работал ни один WebSocket к шлюзу (синхронизация артефактов, голосовой режим, терминал Claude Code). PAC-скрипт пропускал напрямую только `https://`, а Chrome передаёт в PAC адрес WebSocket в виде, который такой шаблон не совпадал, и соединение уходило в тупик. Теперь хост берётся из аргумента PAC, а схема и порт разбираются отдельно.
- Исправлено: рукопожатие WebSocket шло без пароля шлюза: браузеры не применяют к нему правила заголовков. Caddy отвечал 401, и каждая такая попытка засчитывалась как подбор пароля, вплоть до бана IP пользователя. Шлюз теперь авторизует WebSocket своей подписанной cookie.
- Исправлено: в Firefox не отображались артефакты. Открывая панель, Claude дописывает `?artifact=…` в адрес страницы, а обработчик заголовков требовал точного совпадения адресов предков фрейма. Теперь предки сверяются по origin.

### Веб-поиск

- Исправлено: не загружались иконки сайтов в цитатах веб-поиска. Шлюз переписывает и проксирует только адреса иконок Google (`/s2/favicons`, `t0.gstatic.com/faviconV2`), без cookie Claude; остальной Google через шлюз недоступен.

### Шлюз

- Исправлено: условные запросы (`If-Modified-Since`/`If-None-Match`) к переписываемым документам, скриптам и стилям сверялись с исходником. Ответ 304 сохранял устаревшие или повреждённые копии в браузере и в кэше Cloudflare: так держался испорченный `s.js`.
- Исправлено: проверка бана для WebSocket-запросов уходила как апгрейд на `claude.ai/__ban-check`, а не обрабатывалась шлюзом.
- Обрывы запросов при уходе со страницы больше не записываются в лог как ошибки upstream.

### Обновление

- Сервер: нужны новые `gateway.js` и маршрут `@websocket` в Caddyfile (см. `server/Caddyfile.template`).
- Расширение 2.0.9 обязательно для работы WebSocket в Chrome и артефактов в Firefox.
- Через шлюз по-прежнему не работают вход через Google/Apple, оплата (Stripe), Google Maps, YouTube-встраивания, Intercom и push-уведомления: эти сервисы привязаны к claude.ai или к прямому соединению браузера.

## 2.0.8 — 2026-10-16

### Вход по почте

- Исправлено: вход по ссылке из письма не работал, `send_magic_link` отвечал `400 invalid_request_error`. Claude требует токен невидимой hCaptcha, а расширение блокировало её загрузку. Теперь hCaptcha (`hcaptcha.com` и поддомены) идёт через защищённый CONNECT-маршрут шлюза, то есть с того же IP сервера, что видит Claude. В Firefox это касается только вкладок Claude, hCaptcha на других сайтах не затрагивается.

### Шлюз и Cloudflare

- Исправлено: Cloudflare кэшировал закрытые паролем ответы шлюза и раздавал их без авторизации. Закэшированная копия `s.js` (Sift) была повреждена, отсюда `ERR_CONTENT_DECODING_FAILED`. Шлюз теперь отправляет `Cloudflare-CDN-Cache-Control: no-store`; кэшироваться на краю могут только публичные хешированные ассеты Claude.
- Исправлено: функция Cloudflare «Email Address Obfuscation» встраивала в страницы Claude скрипт, который блокирует CSP Claude. Ответы шлюза помечены `Cache-Control: no-transform`.
- Исправлено: HTTP 525 при загрузке страницы Claude. TLS front door держал не больше 256 соединений, а Cloudflare открывает к серверу отдельное соединение на каждый параллельный запрос. Теперь лимит 1024, передача данных идёт через `poll()`, а при кратком переполнении соединение ждёт свободного слота до 5 секунд.

### Проверки

- Сквозная проверка на Windows 11 через рабочий шлюз. Chromium-сборка: claude.ai открывается через шлюз, hCaptcha загружается через CONNECT, `send_magic_link` отвечает 200, открывается экран «click the link sent to…». Firefox 158: запросы hCaptcha проходят так же, как без расширения. Firefox под управлением WebDriver Claude отклоняет и без расширения, поэтому вход в Firefox подтверждается вручную.

### Известные ограничения

- Вход через Google и Apple через шлюз не работает: OAuth-провайдер не принимает чужой origin.

### Обновление

- Добавлено разрешение на доступ к `*.hcaptcha.com`. Chrome и Firefox попросят подтвердить его при обновлении.

## 2.0.7 — 2026-10-15

### Firefox

- Исправлено: расширение блокировало интернет во всём Firefox. Оно ставило глобальный прокси `127.0.0.1:9` и блокировало все запросы профиля, ломало WebRTC на других сайтах и требовало доступ к приватным окнам. Без этого доступа Claude не открывался.
- Через шлюз теперь идут только Claude, его артефакты и библиотеки, которые запрашивают страницы Claude. Остальные сайты, настройки прокси и WebRTC в Firefox не меняются. Отдельный профиль и доступ к приватным окнам не нужны.
- При обновлении снимаются настройки прокси и WebRTC, оставленные предыдущими версиями, даже если шлюз ещё не настроен.
- Артефакты и CDN из Claude идут через защищённый HTTPS CONNECT шлюза. Авторизация передаётся заголовком, у каждой сессии свой ключ изоляции соединений. До готовности маршрута такие запросы блокируются.
- Неизвестные и нешифрованные адреса из страниц Claude и artifact-фреймов блокируются, в том числе из sandbox-фреймов и blob workers. Ссылки, открытые из Claude, работают как обычная навигация.
- Packaged-правила больше не блокируют общие CDN (jsDelivr, Google Fonts и др.) для других сайтов.
- Firefox-пакет переведён на Manifest V2 с постоянной фоновой страницей. Совместимость артефактов (`frame-ancestors`, CORS) обеспечивает native-обработчик заголовков без чтения тела ответа.

### Chrome и общее

- Исправлено: перенастройка прерывалась, если скрипт отпечатка ещё не был зарегистрирован. Из-за этого после перезапуска браузера или смены разрешений маршрут мог не подняться.
- Поведение Chromium-сборки не изменилось: отдельный профиль, ограничение всего профиля.

### Сборка и проверки

- В CI добавлены нативные проверки в Firefox 158: маршрутизация только трафика Claude, отсутствие прямого подключения при отказе релея, WebRTC посторонних сайтов, совместимость артефактов.
- Firefox подписывается в AMO, затем содержимое подписанного XPI сверяется со сборкой. Релиз публикуется только для ещё не выпущенной версии и только после проверки загруженных файлов.
- Версия 2.0.6 была подписана в AMO, но не опубликована: `web-ext sign` записывал служебный `.amo-upload-uuid` в проверяемую сборку, и сверка с XPI останавливала релиз. Теперь подписывается копия сборки.

### Обновление

- Если на прежней версии в Firefox пропал интернет, обновитесь до 2.0.7. Сразу восстановить доступ можно, отключив расширение в `about:addons`.
