# Панель управления шлюзом

Локальная веб-панель для администратора шлюза. В ней видны пользователи и их состояние, нагрузка на шлюз и сервер. Через неё можно добавить пользователя, сменить ему пароль, удалить его и снять бан с IP.

Панель работает на вашем компьютере и ходит на сервер только по SSH. На сервере не открывается ни одного нового порта и не появляется ни одного публичного адреса.

## Установка и запуск

1. **Node.js 18 или новее.** macOS: `brew install node` или установщик с [nodejs.org](https://nodejs.org). Windows: установщик с nodejs.org. Linux: пакет `nodejs`. Проверка: `node -v`.
2. **Вход на сервер по SSH-ключу.** Панель не умеет вводить пароль SSH. Команда `ssh root@<сервер> true` должна пройти без вопросов. Если сервер просит пароль, один раз выполните:
   ```sh
   ssh-keygen -t ed25519          # только если ключа ещё нет
   ssh-copy-id root@<сервер>
   ```
   Windows (PowerShell): `type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<сервер> "cat >> ~/.ssh/authorized_keys"`.
3. **Репозиторий на своём компьютере:** `git clone https://github.com/JFT-git/claude_for_browes.git`. Обновление панели — `git pull` в этой папке.
4. **Запуск.**
   - macOS: двойной щелчок по `dashboard/start.command`. Если Finder не открывает файл (репозиторий скачан ZIP-архивом), нажмите на нём правой кнопкой → «Открыть».
   - Windows: двойной щелчок по `dashboard\start.cmd`.
   - Linux или Терминал: `node dashboard/dashboard.js` в папке репозитория.

При первом запуске панель спросит SSH-адрес сервера и каталог установки и запомнит их в `~/.config/claude-gateway/dashboard.json`. Следующие запуски обходятся без вопросов. Другой сервер можно указать сразу: `node dashboard/dashboard.js root@203.0.113.10` (этот адрес тоже запомнится).

Панель печатает ссылку вида `http://127.0.0.1:8790/#token=…` и открывает её в браузере. Окно Терминала держите открытым, пока работаете с панелью. Остановить панель — Ctrl+C. Если по SSH войти не получилось, панель подскажет в Терминале, что сделать.

| Параметр | Значение по умолчанию | Что задаёт |
|---|---|---|
| `<ssh-адрес>` | запомненный | `пользователь@сервер` или `Host` из `~/.ssh/config` |
| `--dir` | запомненный или `/root/claude-browser` | каталог установки на сервере |
| `--port` | `8790` | локальный порт; если занят, берётся следующий свободный |
| `--interval` | `5` | как часто обновлять данные, в секундах |
| `--no-open` | — | не открывать браузер, только напечатать ссылку |

На сервере должна быть версия с `admin.sh`. Если панель пишет, что `admin.sh` не найден, обновите сервер: `git pull && bash install.sh` в клоне репозитория на сервере (см. раздел «Обновление сервера» в README).

## Что показывает панель

- **Предупреждения.** Front door отказал в соединении, потому что заняты все 1024 слота. У шлюза кончается память. Не готов маршрут CONNECT. У пользователя истекла сессия Claude. Есть заблокированные IP. Cookie лежат на старом общем ключе.
- **Нагрузка.** Запросы в минуту и коды ответов, включая 429 от Claude. Одновременные запросы, WebSocket и туннели CONNECT, число активных пользователей. Трафик. Время ответа Claude и задержка самого шлюза. История за 1, 6 или 24 часа хранится в памяти шлюза и сбрасывается при его перезапуске.
- **Пользователи.** Вошёл ли пользователь в Claude, как зашифрованы его cookie на диске, подключён ли он сейчас, когда был активен, запросы и трафик за 24 часа.
- **Сервер.** CPU и память каждого контейнера, нагрузка, память и диск сервера.
- **Защита.** Сколько файлов cookie зашифровано ключом от пароля и сколько ключей сейчас в памяти. Состояние маршрута CONNECT, бэкапы, заблокированные IP.

Число одновременных соединений front door видно, только если в `.env` задано `FRONTDOOR_DIAGNOSTICS=1`. После изменения перезапустите frontdoor: `docker compose up -d frontdoor`.

## Действия

| Действие | Что происходит на сервере |
|---|---|
| Добавить | Создаётся пароль, Caddy перечитывает настройки без перезапуска. Пароль показывается один раз. |
| Новый пароль | Старый пароль перестаёт работать. Туннели, WebSocket и WebSocket-cookie этого пользователя закрываются. Сессия Claude сохраняется, если ключ пользователя ещё в памяти шлюза (пользователь был активен в последний час). Иначе пользователю нужно снова войти в Claude. |
| Удалить | Пароль удаляется из Caddy. Шлюз закрывает соединения пользователя и стирает ключ из памяти. Файл с cookie удаляется, архивная копия не остаётся. Остальные пользователи подключения не теряют. |
| Разблокировать IP | Снимает бан, наложенный после 10 неверных паролей за 15 минут. |

Те же действия доступны в консоли сервера:

```sh
cd /root/claude-browser
./admin.sh status        # всё, что видит панель
./admin.sh add alice     # печатает {"user":…,"password":…}
./admin.sh reset alice
./admin.sh remove alice
./admin.sh unban 198.51.100.7
./admin.sh retire-legacy-key   # удалить старый общий ключ, когда он больше не нужен
```

## Безопасность панели

- Страница слушает только `127.0.0.1`. Запросы с чужим заголовком `Host` отклоняются, это защита от DNS rebinding.
- Каждый вызов API требует случайного токена, созданного при запуске. Токен передаётся во фрагменте ссылки: браузер не отправляет фрагмент на сервер. После загрузки страница убирает токен из адресной строки.
- Изменения принимаются только как JSON с собственного origin панели. Сторонний сайт не может отправить такой запрос без preflight, а на preflight панель не отвечает.
- Пароли проходят через память один раз: они не попадают в логи панели, в файлы и в историю браузера. После закрытия окна с паролем он удаляется со страницы. На сервере `caddy hash-password` получает пароль через stdin, а не в командной строке.
- Сервер отдаёт панели только счётчики и состояния. Значения cookie, хэши паролей, адреса страниц и IP пользователей (кроме забаненных) в ответ не входят.

### Отдельный SSH-ключ только для панели

Ключу можно запретить всё, кроме команд панели. Добавьте строку в `/root/.ssh/authorized_keys` на сервере:

```text
restrict,command="/root/claude-browser/admin.sh --ssh" ssh-ed25519 AAAA… dashboard
```

В режиме `--ssh` скрипт берёт команду из `SSH_ORIGINAL_COMMAND` и проверяет каждое слово. Подходят только `status`, `watch`, `add`, `reset`, `remove` и `unban` с корректными аргументами. Укажите этот ключ для панели через `~/.ssh/config`:

```text
Host gateway-dashboard
    HostName 203.0.113.10
    User root
    IdentityFile ~/.ssh/gateway_dashboard
    IdentitiesOnly yes
```

После этого запуск такой: `node dashboard/dashboard.js gateway-dashboard`.

## Неполадки

| Симптом | Что сделать |
|---|---|
| «Нет связи с сервером по SSH» | Проверьте `ssh <адрес> true`. Панель не умеет вводить пароль SSH, нужен вход по ключу. |
| «Шлюз не ответил на служебный запрос» | На сервере старый `gateway.js` без служебного API или контейнер gateway не запущен. Обновите сервер через `install.sh`. |
| «Нет доступа: откройте ссылку с токеном» | Откройте ссылку из терминала, где запущена панель. После перезапуска панели токен меняется. |
