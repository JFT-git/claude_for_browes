# Настройка клиента

Основная часть инструкции описывает Chromium-сборку. Firefox Desktop 140+ описан в отдельном разделе ниже: ему не нужен отдельный профиль, и он не меняет работу других сайтов.

## Что получить от администратора

- Ссылку на расширение в [Chrome Web Store](https://chromewebstore.google.com/detail/gateway-connector-for-cla/gimbjmikcifpmiiohgpehkkcknkcccif). Для Firefox — подписанный `.xpi` с `https://<gateway-host>/__ext/`
- Gateway host, например `claude.example.com`
- Персональные gateway username и password

Gateway password — отдельный пароль для входа в шлюз, не пароль Claude.

## Создайте отдельный профиль

Создайте новый профиль Chrome или Edge и используйте его только для Claude через этот шлюз. Пока расширение активно, профиль ограничен: разрешены точный HTTPS-origin шлюза и известные Claude/artifact/CDN endpoints; неизвестные сетевые адреса блокируются. WebRTC и network prediction privacy settings относятся ко всему профилю, не только к вкладке Claude. Не используйте этот профиль для обычного веб-сёрфинга или других приложений.

## Установите и настройте расширение

Используйте расширение версии 2.0.5 или новее. Minimum Chrome version — 125 из-за поддержки OOPIF в debugger API.

1. В выделенном профиле откройте [страницу расширения в Chrome Web Store](https://chromewebstore.google.com/detail/gateway-connector-for-cla/gimbjmikcifpmiiohgpehkkcknkcccif) и нажмите **Установить**. Edge сначала попросит разрешить расширения из других магазинов. Обновления Chrome ставит сам.
2. Если расширение раньше стояло через **Load unpacked**, удалите старую копию на `chrome://extensions` или `edge://extensions`: две копии одновременно мешают друг другу. У версии из магазина свои настройки, введите их заново.
3. Без магазина: `chrome://extensions` → **Developer mode** → **Load unpacked**. Выберите `extension/dist/chrome` или распакованный zip с `https://<gateway-host>/__ext/` — папку, где находится `manifest.json`.
4. Откройте настройки расширения и введите host без `https://` и пути, username и password.
5. Нажмите **Сохранить и разрешить** и подтвердите запрошенные origin permissions.
6. Chromium-пакет требует разрешение `debugger`; Chrome показывает соответствующее предупреждение при установке. Оно нужно для ограниченной совместимости artifact iframe. Chrome также показывает системный баннер отладки, пока подключена вкладка шлюза — это ожидаемо.
7. Проверьте, что расширение показывает активный защищённый маршрут. Если статус не подтверждён, неизвестные запросы остаются заблокированными; не продолжайте считать клиент готовым.

Расширение отправляет gateway credentials только на точный настроенный HTTPS-origin. Для artifact/CDN tunnel оно получает отдельный токен у gateway; этот токен ограничен назначением и временем жизни, а не является вашим gateway password.

Перед открытием artifact-маршрута Chromium проверяет фиксированный HTTPS `HEAD` без тела к jsDelivr через CONNECT и должен получить успешный proxy-auth callback. Redirect запрещён, таймаут — 8 секунд. Пока проверка не завершилась, artifact requests остаются заблокированными; в popup может отображаться состояние проверки. Это служебный запрос к заданному CDN URL, а не передача содержимого страницы.

После обновления расширения сделайте hard reload в Claude (`Cmd+Shift+R` на Mac), чтобы убрать старые скрипты из вкладки. Распакованную копию перед этим перезагрузите на странице управления extensions; версию из магазина Chrome перезапускает сам.

## Firefox Desktop

Начиная с 2.0.7 Firefox-сборку можно ставить в обычный профиль. Через шлюз идут только Claude, его артефакты и библиотеки, которые запрашивают страницы Claude. Остальные сайты, настройки прокси и WebRTC в Firefox не меняются.

1. Установите подписанный `.xpi` с `https://<gateway-host>/__ext/`. Для проверки исходников можно открыть `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» и выбрать `extension/dist/firefox/manifest.json`.
2. В настройках расширения введите host, username и password, нажмите **Сохранить и разрешить** и подтвердите доступ к шлюзу.
3. Дождитесь статуса «Защищённый маршрут активен» и откройте `https://claude.ai`.

Разрешать запуск в приватных окнах не нужно. Без этого разрешения расширение не действует в приватных окнах, и Claude там откроется напрямую. Если вы ставили версию до 2.0.7 и в Firefox пропал интернет, обновите расширение: при обновлении оно вернёт прежние настройки прокси и WebRTC. Сразу восстановить доступ можно, отключив расширение в `about:addons`.

## Ограничения функций

- Для inline artifact Documents Chromium использует debugger только на вкладках с точным gateway origin и их OOPIF frames. Для ответа, требующего изменения заголовков, расширение ограниченно читает body в памяти (до 8 MiB); если такое изменение не удаётся, запрос блокируется. Для изменяемого ответа удаляется `X-Frame-Options`, а gateway origin добавляется в существующий `frame-ancestors`, только если та уже разрешает Claude. Остальные CSP directives и политики сохраняются. Ответы с `Content-Disposition: attachment` проходят как обычные загрузки браузера без буферизации тела этим механизмом. Совместимость каждого артефакта и загрузки не гарантируется.
- Не открывайте DevTools для вкладки Claude, пока расширение обрабатывает артефакты. Если debugger занят или был отключён, обработка fail-closed. Закройте DevTools и явно перезагрузите/откройте вкладку Claude заново; если debugger не подключился при первом открытии, перезагрузите страницу после того, как popup покажет готовый маршрут.
- Google/Apple OAuth может завершиться `origin_mismatch`; поддерживаемого обхода нет.
- Неизвестные внешние хосты блокируются. WebSocket к шлюзу (голосовой режим, синхронизация артефактов, терминал Claude Code) работает с 2.0.9.
- Через шлюз не работают функции, привязанные к домену claude.ai у сторонних сервисов: вход через Google/Apple, оплата и управление подпиской (Stripe), карты Google Maps, встроенные YouTube-видео, чат поддержки Intercom, push-уведомления. Подпиской управляйте на claude.ai напрямую.
- Fingerprint ограничен частью browser APIs. Он не обеспечивает анонимность, не меняет аппаратные признаки и не скрывает IP от самого gateway или сетевого провайдера при прямом CONNECT.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Статус маршрута не активен | Host/user/password, разрешения, доступность шлюза, доменный TLS и сертификат IP CONNECT; повторите проверку из настроек. |
| Проверка CONNECT остаётся fail-closed после обновления расширения | Если Chrome использует сохранённые proxy credentials, выполните полный перезапуск браузера или дождитесь истечения прежнего 15-минутного токена. Расширение не очищает общую browser-auth cache. |
| Claude просит войти | Cookie-сессия могла истечь. Войдите заново; gateway сохранит новую session cookie на сервере. |
| Claude загружается, но artifact preview пустой | Поддерживается ли host и разрешает ли embedding CSP. Не выключайте CSP и не добавляйте произвольный домен в allowlist. |
| Google/Apple OAuth возвращает `origin_mismatch` | Это ограничение redirect-origin. В документации нет безопасного исправления. |
| После смены настроек соединения прекращаются | Это fail-closed поведение. Проверьте конфигурацию, верните gateway и заново проверьте защищённый маршрут. |

## Приватность

Обычный Claude traffic проходит через gateway; оператор gateway может получить доступ к session cookie после расшифрования. Artifact CONNECT идёт напрямую на IP gateway и сохраняет TLS к исходному artifact/CDN host, поэтому gateway видит metadata туннеля, но не TLS-содержимое. Cloudflare при включённом proxy видит обычный gateway traffic, но не прямой CONNECT. Подробности — [SECURITY.md](../SECURITY.md).
