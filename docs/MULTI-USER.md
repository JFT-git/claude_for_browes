# Несколько пользователей

Один gateway может хранить отдельную Claude-сессию и отдельный вход в шлюз для каждого пользователя. Это не означает, что ёмкость или поддержка функций линейно растёт с числом аккаунтов: измерения нагрузки в этом репозитории отсутствуют.

## Потоки и границы

```text
Браузер Alice --HTTPS + gateway Basic--> Caddy --> Gateway --> cookies/alice.json --> Claude
Браузер Bob   --HTTPS + gateway Basic--> Caddy --> Gateway --> cookies/bob.json   --> Claude
Браузер       --HTTPS CONNECT token--> TLS front door --> Gateway --> artifact/CDN origin
```

- Caddy проверяет персональные gateway credentials и передаёт gateway подтверждённое имя пользователя.
- Gateway выбирает cookie-jar по этому имени. Claude cookies остаются на сервере и не передаются клиентскому браузеру.
- Артефакты используют отдельные короткоживущие proxy tokens. В CONNECT-туннель не передаются Claude session cookies. Выдача CONNECT ограничена allowlist хостов и не даёт произвольного доступа в Интернет.
- Общая инфраструктура всё равно использует один исходящий IP сервера для обычных upstream-запросов. Разные локальные gateway users не получают отдельные IP.

## Добавление пользователя

В каталоге деплоя запустите:

```sh
./add-user.sh alice
```

Скрипт генерирует длинный пароль, выводит его один раз, создаёт запись Basic auth и cookie-слот. Caddy перечитывает настройки через свой внутренний сокет, без перезапуска: соединения остальных пользователей не рвутся. Передайте пользователю его gateway host, имя и пароль по защищённому каналу. Не используйте пароль Claude как gateway password.

Пароль к шлюзу — это и ключ к cookie пользователя: из него выводится ключ шифрования файла (см. [SECURITY.md](../SECURITY.md)). При повторном запуске для существующего имени пароль меняется, туннели и WebSocket пользователя закрываются. Сессия Claude сохраняется, если пользователь был активен в последний час. Иначе ему нужно снова войти в Claude.

Пока пользователь не ввёл новый пароль в настройках расширения, его браузер продолжает отправлять старый. После 10 отказов за 15 минут шлюз блокирует этот IP на 15 минут, а блокировка касается всех, кто выходит в интернет с того же адреса. Меняйте пароль, когда пользователь готов сразу ввести новый, или снимите блокировку: `./admin.sh unban <IP>` или кнопка в [панели](DASHBOARD.md).

То же самое, а также нагрузку и состояние пользователей, можно делать из локальной панели: [DASHBOARD.md](DASHBOARD.md).

## Удаление пользователя

```sh
./remove-user.sh alice
```

Удаление закрывает доступ к шлюзу и стирает cookie-файл пользователя без архивной копии: архив был бы действующей сессией Claude. Gateway отзывает только proxy-токены, туннели, WebSocket и WebSocket-cookie этого пользователя и не перезапускается, поэтому остальные пользователи соединений не теряют. Если на сервере старый gateway без служебного API, скрипт перезапускает gateway, как раньше.

## Первый вход в Claude

Пользователь ставит расширение из [Chrome Web Store](https://chromewebstore.google.com/detail/gateway-connector-for-cla/gimbjmikcifpmiiohgpehkkcknkcccif) в отдельный профиль Chrome или Edge (в Firefox — подписанный `.xpi`, отдельный профиль не нужен), вводит host и gateway credentials в настройках расширения и завершает вход в Claude. При входе gateway принимает session cookies и сохраняет их в jar этого пользователя. Magic-link и OAuth зависят от текущих правил провайдера; Google/Apple могут вернуть `origin_mismatch`, для этого не заявлен обход.

Firefox Desktop 140+ с версии 2.0.9 открывает артефакты через тот же защищённый CONNECT-маршрут; см. [SETUP-CLIENT.md](SETUP-CLIENT.md#firefox-desktop).

## Ёмкость и операции

Не используйте старые оценки RAM/CPU/полосы или заявленное число одновременных пользователей как capacity guarantee. Нагрузка зависит от стриминга, вложений, CDN cache, лимитов upstream и сети сервера. Для нескольких пользователей измерьте ресурсы на своём сервере при ожидаемой нагрузке и задайте свои пределы.

Gateway session tokens действуют 15 минут и продлеваются расширением при доступном шлюзе. Закрытие браузера, потеря gateway, отказ сертификата или отзыв сессии могут временно блокировать artifact/dependency запросы. Неизвестные внешние hostnames блокируются. WebSocket к шлюзу (голос, синхронизация артефактов, терминал) с 2.0.9 авторизуются подписанной cookie шлюза.

Резервируйте `.env`, cookie-файлы, Caddyfile и ключ резервных копий. Cookie-файлы в бэкапе зашифрованы паролями пользователей и без них не открываются. Секреты не должны попадать в Issue, логи или репозиторий.
