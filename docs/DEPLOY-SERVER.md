# Deploy the server

One-time server setup. Tested on a DigitalOcean droplet (1 vCPU / 2GB) running Ubuntu + Docker.

## 1. Prereqs

- A server with a public IP in a region where claude.ai is reachable
- Docker + docker compose plugin
- A domain (e.g. `claude.example.com`) — Cloudflare in front is recommended (hides the origin and smooths provider-level connection resets)

## 2. Copy files

Put on the server, e.g. in `/root/claude-browser/`:

```
server/compose.yaml
server/Caddyfile          (generated by configure.sh)
gateway/gateway.js  →  gateway/src/gateway.js
```

Layout on the server:

```
/root/claude-browser/
├── compose.yaml
├── Caddyfile
├── gateway/
│   ├── src/gateway.js
│   └── cookies/          (session cookies land here)
```

## 3. Configure

```sh
./configure.sh claude.example.com
```

Then edit the generated `server/Caddyfile`:
- set `__BASIC_AUTH_USER__` (e.g. a client name)
- set `__BASIC_AUTH_HASH__` — generate with:
  ```sh
  docker run --rm caddy:2 caddy hash-password --plaintext 'the-password'
  ```

## 4. DNS / Cloudflare

Point `claude.example.com` at the server. If using Cloudflare, set the record to **Proxied** (orange cloud) and SSL/TLS mode **Full**.

## 5. Start

```sh
cd /root/claude-browser
docker compose up -d
```

This starts two containers: `gateway` and `caddy`.

## 6. Add users

The gateway is multi-user: each user gets their own Claude account and cookie file.

```sh
./add-user.sh alice                 # random strong password, shown once
./add-user.sh bob 'his-long-password'  # or set your own (min 12 chars); re-run to change it
./remove-user.sh bob
```

This adds a basic_auth credential to `Caddyfile`, creates a cookie slot `gateway/cookies/<user>.json`, and restarts Caddy.

## 7. Users log in themselves (self-service)

No remote browser needed for users. Each user:

1. Installs the extension, enters their host + user + pass in Options
2. Opens `https://claude.ai` → sees the Claude login page (no cookies yet)
3. Enters their email → clicks the magic-link from their inbox
4. Claude sets session cookies → the gateway **captures** them into `cookies/<user>.json`
5. Done — they're authenticated

Verify a user is captured:
```sh
curl -u alice:her-password https://claude.example.com/api/bootstrap   # → 200 JSON
```

## 8. Hand out to clients

Give each client:
- the `extension/` folder (already configured by `configure.sh`)
- their basic_auth user + password
- `docs/SETUP-CLIENT.md`

## Updating cookies later

Sessions are long-lived. If a user's session expires (gateway returns 401 from claude.ai for them), they just log in again through the gateway (step 7) — cookies are re-captured automatically.

## Multi-client

Multi-user works out of the box. See [MULTI-USER.md](MULTI-USER.md) for architecture and server capacity calculations.

## Recommended: use `install.sh`

`bash install.sh` in the repo root does all of the above interactively (domain, first user, secrets in `.env`,
encrypted cookies, daily encrypted backups, extension build) and serves the ready-made extension to your users at
`https://<domain>/__ext/` (behind basic_auth).

## Operations

| Task | Command (in the deploy dir) |
|---|---|
| Session status of all users | `curl -u <admin> https://<domain>/__admin/status` |
| Backup now | `./backup.sh` (daily via cron; key in `/root/.claude-gateway-backup.key` — **keep a copy off the server**) |
| Restore | `./restore.sh backups/state-<date>.tar.gz.enc` |
| Telegram alerts | set `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` in `.env`, then `docker compose up -d` |
| Update gateway | copy new `gateway/gateway.js` to `gateway/src/gateway.js`, `docker compose restart gateway` |
